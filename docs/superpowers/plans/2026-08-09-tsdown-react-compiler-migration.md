# Tsdown and React Compiler Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Task 6 is interactive (per-fix approval by Jakub) and must run in the main session, not in a fire-and-forget subagent.

**Goal:** Rebuild the `react-compiler` branch on `development`, keeping only the tsdown build switch, then add React Compiler to the `react-library` template build and enable the compiler-powered lint rules, in one PR targeting `development`.

**Architecture:** The branch is reset hard to `development` and two commits are cherry-picked (the design doc and `Switch to Tsdown`); all generated files are regenerated by Carson rather than hand-merged. React Compiler is wired through the officially supported Babel bridge (`@rolldown/plugin-babel` + `reactCompilerPreset()` from `@vitejs/plugin-react`) in the `react-library` template's `tsdown.config.ts` and `vite.config.ts`; `ui` is the only consumer. Lint rules from `eslint-plugin-react-hooks@7.1.1` are uncommented in `eslint-config` and violations fixed one at a time with Jakub's approval.

**Tech Stack:** npm/turbo monorepo, Carson templates (EJS), tsdown 0.22.x, @rolldown/plugin-babel 0.2.x, @vitejs/plugin-react 6.x, babel-plugin-react-compiler 1.0, eslint-plugin-react-hooks 7.1.1, changesets.

**Spec:** `docs/superpowers/specs/2026-08-09-tsdown-react-compiler-migration-design.md`

## Global Constraints

- Branch `react-compiler`, single PR targeting `development`. Backup ref `react-compiler-old` kept until merge; nothing force-pushed until the PR is ready.
- tsdown bumped from `^0.17.0` to `^0.22.0` (latest is 0.22.14, verified 2026-08-09).
- Compiler scope: `react-library` template only (`ui` is its only consumer). No compiler for `carson` and `cli` builds. No `library` template build changes beyond the tsdown switch. No native Rust compiler wiring.
- Lint severities come from the commented block in `packages/eslint-config/source/rules/react-hooks.ts`, uncommented as written. Dedup decision (Jakub, 2026-08-09): the new compiler-generation rule names win; classic `rules-of-hooks` and `exhaustive-deps` go to `'off'` with a comment naming the replacement.
- Every lint-violation fix is a real code change or a justified disable comment, individually approved by Jakub.
- Never hand-edit machine-owned files: `packages/*/docs/**`, `typedoc.config.cjs`, `CONTRIBUTING.md`, `.github/workflows/*.yaml`, generated configs (`tsdown.config.ts`, `vite.config.ts`, `tsconfig*.json`, `package.json` scripts). Change the template or config, then regenerate with `npm run prepare` (also runs automatically after `npm install`).
- Never hand-merge `package-lock.json` or `.carson/project.snapshot` files: take `development`'s version, regenerate.
- carson-templates smoke tests (`packages/carson-templates/tests/smoke-tests.test.ts`) are never run locally; CI covers them.
- Repo commit style: short sentence-case imperative without prefixes (e.g. "Switch to Tsdown").
- The working tree has two pre-existing untracked entries, `.claude/` and `CLAUDE.md` at the repo root. Leave them untracked; never commit or delete them. `git status --porcelain` checks in this plan mean "nothing besides those two lines".

## Verified facts the tasks rely on

Verified 2026-08-09 against npm and the installed workspace; do not re-derive:

- `tsdown` latest: 0.22.14. Options `entry`, `outDir`, `platform`, `unbundle`, `plugins` confirmed in current docs; `copy` and `platform: 'neutral'` are confirmed empirically in Task 3 (ui build must emit `build/styles.css` and both woff2 files).
- `@rolldown/plugin-babel` latest: 0.2.3. API: **default export** `babel`; options `presets`, `plugins`, `include`, `exclude`, `sourceMap`, `overrides`. Default `include` already covers `.js/.jsx/.ts/.tsx`. It does NOT have a `babelConfig` option (the spec's sketch is outdated on this point; the tsdown recipe at https://tsdown.dev/recipes/react-support uses `presets: [reactCompilerPreset()]`). Required peers: `@babel/core` `^7.29.0 || ^8.0.0-rc.1` and `rolldown` (satisfied transitively by tsdown). README recommends `@types/babel__core` for TypeScript.
- `@vitejs/plugin-react` latest: 6.0.5, exports `reactCompilerPreset`. Peers: `vite` `^8.0.0` (required), `@rolldown/plugin-babel` `^0.1.7 || ^0.2.0` (optional), `babel-plugin-react-compiler` `^1.0.0` (optional).
- `babel-plugin-react-compiler` latest: 1.0.0. Compiler target defaults to React 19, matching `ui`'s peer range, so no extra runtime package is needed.
- `development`'s lockfile resolves `vite` 7.1.2, but every consumer in the tree (`vitest`, `@tailwindcss/vite`, `@storybook/react-vite`, `@storybook/builder-vite`, `@vitest/mocker`) accepts `^8.0.0`, and `DEPENDENCY_VERSIONS` already contains `vite: '^8.0.0'`. Adding `@vitejs/plugin-react` forces vite to 8.x during `npm install`.
- `eslint-plugin-react-hooks@7.1.1` ships 29 rules; only `component-hook-factories` is marked deprecated (so `check-rules` ignores it). Both classic (`rules-of-hooks`, `exhaustive-deps`) and new (`hooks`, `exhaustive-effect-dependencies`) names ship as separate non-deprecated implementations.
- `perfectionist/sort-objects` is `'off'` in eslint-config, so the rules object does not need alphabetical re-sorting.
- `npm run prepare` at the root rebuilds carson + carson-templates and runs `carson update workspace`; it also runs automatically after every `npm install`. Generated `package.json` dependency ranges are refined to the actually installed version on the next regeneration (e.g. `^0.22.0` becomes `^0.22.14` once tsdown is installed), which is why installs are looped until the tree is stable.
